# テニスベア情報取り込みの MVP 方針と画面説明

Refs: #13 / #11

## 目的

テニスベア情報取り込みを、web MVP の入力導線としてどこまで扱うか整理する。

このドキュメントでは、取り込み方式、取り込み対象、対象外とする情報、避けること、画面上の説明文を整理し、後続の貼り付け取り込み実装に進める状態を作る。

## 基本スタンス

ランスケは、テニスベアのイベント募集・申込・決済・参加管理を代替しない。

テニスベア上でイベントを作成・募集・参加確定した主催者が、自分のイベント情報をランスケに取り込み、当日の対戦表作成・進行補助に使うための機能として扱う。

MVPでは、ログイン連携やテニスベア側への書き戻しは行わない。

また、テニスベアへの大量アクセス、定期取得、認証情報の預かりは行わない。

取り込み方式は、URL入力による補助取得に加えて、主催者本人によるテキスト貼り付け取り込みを fallback として用意する。

取り込んだ情報はそのまま確定せず、入力フォームに反映し、主催者が内容を確認・必要に応じて編集したうえで「この内容で生成」を押す。

## 1. MVP の取り込み方式

MVP では、以下の方式を基本とする。

1. 主催者がテニスベアのイベント URL を入力する
2. URL を `source_url` として保存する
3. 主催者がテニスベア画面上の情報をコピーして貼り付ける
4. 「取り込み」ボタンを押す
5. 貼り付けテキストから event / participant 候補を抽出する
6. 抽出結果を入力フォームに反映する
7. 主催者がフォーム上で内容を確認・必要に応じて編集する
8. 「この内容で生成」を押して対戦表生成に進む

抽出結果専用の確認画面は作らない。

「確定」ボタンも設けない。

主催者確認とは、入力フォームに反映された内容を見たうえで「この内容で生成」を押すこととする。

## 2. 取り込み対象にする情報

### 2.1 イベント情報

イベント詳細画面から簡単に取得できる情報は、MVP の取り込み対象にする。

取り込み対象の候補は以下。

* イベント名
* 開催日時
* 開催場所
* コート情報
* 募集レベル
* 備考
* source_url

ただし、generate に必須な情報と、表示・補助情報として使う情報は分けて扱う。

生成に必須な情報は、コート数、参加者一覧、schedule_type などである。

イベント名、日時、場所、コート情報、募集レベル、備考は、入力補助・共有表示・当日の確認用として扱う。

### 2.2 イベント情報として不要なもの

以下は MVP の取り込み対象にしない。

* 参加者数
* キャンセル待ち情報
* 未確定参加者情報

参加者数は、実際に取り込まれた参加者情報から算出すればよい。

MVPでは、キャンセル待ちや未確定参加者は対戦表生成対象に含めない。

## 3. 参加者情報

### 3.1 取得する情報

参加者情報として、以下を取り込み対象にする。

* source_user_id 相当
* 名前
* 年代
* 性別
* レベル
* テニス歴

これらは、対戦表生成そのものには必須ではない。

ただし、主催者が参加者を確認しやすくするため、また将来の player / source_player 的な拡張に備えるため、metadata として保持できる余地を残す。

core には、名前・年代・性別・レベル・テニス歴などの参加者情報は渡さない。

core は player 情報を知らず、web 側が slot / assignment を participant 表示名に解決する。

### 3.2 参加者情報として不要なもの

以下は MVP の取り込み対象にしない。

* 主催回数
* 参加回数
* ベア友情報
* バッジ情報
* 自己紹介
* ベアログ

これらは、当日の対戦表作成・進行補助に直接必要ではない。

また、参加者情報の過剰な取得・再配布につながる可能性があるため、MVP では扱わない。

## 4. やらないこと

MVP では以下を行わない。

* ログイン後ページの自動取得
* テニスベアの認証情報を預かる
* 参加者一覧を定期クロールする
* 複数イベントを大量取得する
* テニスベア参加者情報をランスケ上で公開・再配布する
* テニスベアの申込導線をランスケ側に置き換える
* テニスベアへの書き戻し
* 外部サービス連携としてのログイン連携

ランスケの役割は、主催者本人が確認できるイベント情報をもとに、当日の対戦表作成・進行補助を行うことに限定する。

## 5. バリデーションとエラー表示

手動貼り付け自体は許可する。

ただし、「取り込み」ボタン押下時に検証し、取り込み対象外であれば event / participant には反映しない。

失敗時は入力内容を消さず、エラーを表示する。

エラー文言例は以下。

* 取り込み対象のURLではありません
* イベント情報を読み取れませんでした
* 参加者情報が見つかりませんでした
* 貼り付け内容を確認してください

取り込みに失敗した場合でも、主催者は直接入力でイベント情報・参加者情報を入力できる。

## 6. 画面に出す説明文

テニスベア情報の貼り付け取り込み画面に、取り込み機能の位置づけを説明する案内を置く。

表示形式は以下のどちらかを想定する。

* 「※ テニスベアのイベント情報取り込みについて」というリンクを置く
* クリック / タップでポップアップ表示する

### 6.1 表示文案

```md
※ テニスベアのイベント情報取り込みについて

この機能は、テニスベアで募集・管理しているイベントの情報を、当日の対戦表作成に使いやすくするためのものです。

募集・申込・決済・参加管理はテニスベア側で行い、ランスケでは主催者本人が確認できるイベント情報をもとに、対戦表作成・進行補助だけを行います。

取り込み後は、内容を確認・必要に応じて編集してから使用してください。
```

### 6.2 画面上の注意表示で明記すること

案内では以下を明記する。

* ランスケはテニスベアの募集・申込・決済・参加管理を代替しない
* 主催者本人が、自分のイベント情報を当日の進行補助に使うための機能である
* 取り込んだ情報は、主催者が確認・必要に応じて編集してから使用する
* ログイン連携、書き戻し、大量取得、定期取得は行わない

## 7. 後続実装への引き渡し

### #16 テニスベア貼り付けテキストから event / participant 候補を取り込む

後続の貼り付け取り込み実装では、以下を前提にする。

* source_url 入力欄を用意する
* 貼り付けテキスト入力欄を用意する
* 「取り込み」ボタンを用意する
* 取り込みボタン押下時に URL / テキストを検証する
* 対象外URLや抽出失敗時は event / participant に反映しない
* 入力内容は消さず、エラー表示する
* 抽出結果は event / participant 候補として入力フォームに反映する
* 抽出結果専用の確認画面は作らない
* 「確定」ボタンは作らない
* 主催者確認は「この内容で生成」を押すこととする
* 解析できなかった場合でも、手入力で進められる導線を残す

### #14 event / participant / import / share の保存モデルを設計・実装する

保存モデルでは、以下を検討する。

* `source_type = tennisbear`
* `source_url`
* `pasted_text`
* 抽出された event 候補
* 抽出された participant 候補
* participant metadata

  * source_user_id 相当
  * 名前
  * 年代
  * 性別
  * レベル
  * テニス歴

player / source_player 的な概念を分けるかどうかは、#14 の保存モデル設計時に判断する。

## 8. #13 の結論

* テニスベア取り込みは MVP 必須の入力導線として扱う
* ランスケはテニスベアの募集・申込・決済・参加管理を代替しない
* URL入力とテキスト貼り付けを基本導線にする
* 自動スクレイピング、認証情報保持、定期クロール、大量取得はしない
* イベント詳細画面から簡単に取れるイベント情報は取り込み対象にする
* 参加者数、キャンセル待ち、未確定参加者は MVP では扱わない
* 参加者情報は、id・名前・年代・性別・レベル・テニス歴を対象にする
* 主催回数、参加回数、ベア友情報、バッジ情報、自己紹介、ベアログは対象外にする
* 抽出結果専用の確認画面は作らず、入力フォームに反映する
* 取り込み後、主催者が内容を確認・必要に応じて編集し、「この内容で生成」を押す
