# 💬 問い合わせ / 要望受付

このページでは、Lanske の問い合わせ・要望受付の扱いを整理します。

ver0.1.1 時点では、アプリ内に問い合わせ管理機能は作らず、Google Forms などの外部フォームを使う方針です。

---

## 方針

問い合わせ / 要望受付は、まず外部フォームで受け付けます。

想定:

- Google Forms などで受付フォームを作る
- フォーム URL を README / support docs / アプリ内リンクから案内する
- 回答はスプレッドシート等で管理する
- 必要に応じて GitHub Issue や worklog に転記して開発タスク化する

---

## 外部フォームに寄せる理由

ver0.1.1 では、問い合わせ管理機能をアプリ内に作らない方が運用しやすいです。

理由:

- ログインなし MVP と相性がよい
- 実装コストが低い
- フォーム項目を後から変更しやすい
- スプレッドシートで一覧・集計しやすい
- 要望と不具合報告をまず軽量に受けられる

---

## フォーム項目候補

最初のフォームでは、以下のような項目を想定します。

| 項目 | 必須 | 備考 |
|---|---:|---|
| 種別 | 必須 | 不具合 / 要望 / 質問 / その他 |
| 内容 | 必須 | 自由記述 |
| 発生した画面 | 任意 | TOP / 入力画面 / 対戦表 / 共有URL / その他 |
| 利用環境 | 任意 | PC / iPhone / Android / iPad など |
| ブラウザ | 任意 | Chrome / Safari など |
| 共有URL | 任意 | 調査に必要な場合のみ。公開に注意する |
| 連絡先 | 任意 | 返信が必要な場合のみ |

---

## 注意点

フォームには、公開したくない個人情報や、不要に詳細な参加者情報を入力しないよう案内します。

特に共有URLを送ってもらう場合は、URLを知っている人が対戦表を開ける前提で扱います。

---

## アプリ内リンクの扱い

ver0.1.1 では、アプリ内に問い合わせフォームへのリンクを置くかどうかを別途判断します。

候補:

- TOP 画面の下部に小さく置く
- 対戦表画面の footer 相当に置く
- README / docs のみに留める

まずは README / docs から案内し、利用状況を見てアプリ内リンクを追加する方針でもよいです。

---

## 開発タスク化

フォームで受けた内容は、必要に応じて次のように扱います。

- 明確な不具合: GitHub Issue 化する
- 仕様確認: docs / FAQ へ反映する
- よくある要望: ロードマップ候補に入れる
- 個別事情が強いもの: すぐ実装せず、類似要望が増えるか見る
