# 🧭 Lanske support docs

このディレクトリは、Lanske の公開ユーザー向け support 系ドキュメントの置き場です。

ver0.1.1 時点では、本格的なヘルプサイトやブログ機能は作らず、公開後にユーザーが迷ったとき・要望を伝えたいとき・更新内容を確認したいときの最低限の受け皿を整理します。

---

## 公開 support ページ

公開サイト上の support 入口は以下です。

- [らんすけ サポート](../../web/support/index.html)

アプリ内の右上メニューからも、フィードバックフォームへアクセスできる導線を用意します。

---

## フィードバック / 問い合わせ

らんすけへのご意見・ご質問・不具合報告・改善案は、以下のフォームから送信できます。

- [らんすけ フィードバックフォーム](https://forms.gle/xbXuJsZnfh5QrqjP8)

返信が必要な場合のみ、フォーム内にメールアドレスを入力してください。

共有URLを送る場合は、URLを知っている人が対戦表を開ける点にご注意ください。
公開したくない情報や、不要に詳細な参加者情報は入力しないでください。

詳細は [問い合わせ / 要望受付](feedback.md) を参照してください。

## ver0.1.1 での方針

### まず静的 docs で扱うもの

| 種別 | ver0.1.1 での扱い | 備考 |
|---|---|---|
| FAQ | 静的 docs 候補 | 使い方 / 既知の制限事項で足りない質問が増えたら追加する |
| ヘルプ | 静的 docs 候補 | スクショ付きヘルプは必要になった段階で追加する |
| 問い合わせ / 要望 | 外部フォーム | Google Forms を使い、アプリ側はリンク導線だけに留める |
| ロードマップ | 静的 docs 候補 | 短期 / 中期 / 将来構想を分けて見せる想定 |
| リリースノート | 静的 docs 候補 | 最初は Markdown で十分。DB 管理は後回し |
| 既知の不具合 | 静的 docs 候補 | 既知の制限事項と分ける必要が出たら追加する |

### 今は本格化しないもの

| 種別 | 後回しにする理由 |
|---|---|
| 本格的なヘルプサイト | ver0.1.1 では情報量がまだ少ない |
| ブログ / ニュース機能 | 更新頻度が読めないため、まずは docs で十分 |
| DB 管理のリリースノート | 運用が固まってから検討する |
| ログイン前提の要望管理 | ver0.1.1 はログインなし MVP のため対象外 |
| 詳細な法務レビュー済みページ | 必要になった段階で別途扱う |

## 問い合わせ / 要望受付

問い合わせや要望は、ver0.1.1 時点では Google Forms の外部フォームを使う方針とします。

理由:

- アプリ側に問い合わせ管理機能を作らなくてよい
- ログインなしでも受け付けやすい
- 回答項目を後から調整しやすい
- スプレッドシート連携で要望整理しやすい

---

## FAQ / ヘルプ

FAQ は、`usage-ver0.1.md` と `known-limitations-ver0.1.md` で説明しきれない質問が増えた段階で追加します。

追加候補:

- 共有URLは誰が見られるか
- テニスベア取り込みでうまく名前が取れない場合
- 対応人数・コート数の範囲
- 対戦数を変更できるか
- 保存済み対戦表が見えない場合

スクショ付きヘルプは、操作に迷う箇所が明確になってから追加します。

---

## 利用規約 / プライバシーポリシー

利用規約とプライバシーポリシーは、必要になった段階で別ページとして追加します。

ver0.1.1 時点では、詳細な法務レビュー済み文書の作成までは行いません。

ただし、公開ユーザー向け docs では次の注意点を明確にします。

- ログインなし MVP であること
- 共有URLを知っている人は対象の対戦表を開けること
- 公開したくない情報や個人情報に近い内容は入力しないこと
- テニスベア等の募集・申込・決済・参加管理は代替しないこと

これらは、当面 [ver0.1 既知の制限事項](../known-limitations-ver0.1.md) 側で扱います。

---

## ロードマップ

ロードマップは、最初は静的 docs として扱います。

将来的には、項目ごとにリアクションや要望数を見られる形も検討します。

ver0.1.1 時点では、GitHub Issue / worklog / README の「今後の予定」を優先し、公開ユーザー向けロードマップページは必要になった段階で追加します。

---

## リリースノート / 既知の不具合

リリースノートと既知の不具合一覧は、最初は Markdown の静的 docs として追加する方針です。

DB 管理やアプリ内一覧表示は、更新頻度と運用負荷が見えてから検討します。
