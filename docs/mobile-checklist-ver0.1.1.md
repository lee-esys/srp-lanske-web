# 📱 Lanske ver0.1.1 スマホ実機確認チェックリスト

## 目的

`ver0.1.1` 時点のスマホ実機利用で、公開前・公開直後のブロッカーになりそうな問題がないかを簡易確認する。

このチェックリストは、詳細な性能計測や大規模な UI 改修のための手順書ではなく、現状の動作確認と後続 Issue 化の判断材料として扱う。

対象 Issue:

- #51 ⚡ スマホ実機で共有URL初期表示の体感速度を確認する
- #62 🧪 iOS Chrome / Safari の scroll-to-top 挙動を調査する

---

## 1. 今回の確認範囲

### 確認すること

- [ ] 共有URL初期表示が体感的に極端に遅くない
- [ ] 共有URLのリロード復元ができる
- [ ] generate / regenerate / adopt が通常利用に耐える体感速度で動く
- [ ] 対戦表画面の画面内更新ボタンで再読込できる
- [ ] スマホブラウザの下スワイプ更新が使えるか確認する
- [ ] iOS Safari / Chrome の scroll-to-top 挙動を確認する
- [ ] 問題がある場合、`ver0.1.1` 内で対応するか、後続 Issue に切り出すかを判断する

### 今回やらないこと

- [ ] Lighthouse / WebPageTest などの詳細計測
- [ ] Flutter Web bundle 最適化
- [ ] Firebase Hosting / Firestore / core API の詳細チューニング

- [ ] Flutter Web のスクロール基盤の大きな変更
- [ ] ブラウザ標準の pull-to-refresh 挙動を強制的に再現すること
- [ ] 画面右下の top-scroll フロートボタン追加
- [ ] support 静的ページの作成

- `PrimaryScrollController.none` の利用可否を確認する
- 対戦表画面 / 入力画面 / 一覧画面で挙動差があるか確認する

## 7. 後続 Issue 候補

確認結果によって、必要なら以下を後続 Issue として切り出す。

- スマホ実機で共有URL初期表示が遅い場合の性能改善
- ローディング表示の改善
- pull-to-refresh が効かない場合の更新導線改善
- 画面右下 top-scroll フロートボタンの追加
- `PrimaryScrollController` / `ScrollController` 周辺の scroll-to-top 挙動整理

今回の Issue では、これらの機能追加は行わず、動作確認と判断材料の整理に留める。
