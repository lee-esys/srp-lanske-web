# ダブルス対戦表の進行中・次対戦表示

## 目的

確定済みのダブルス対戦表で、保存されている試合状態から現在の進行対象を導出し、画面上部から該当試合カードへ移動できるようにする。

実行順そのものは保存せず、対戦表の `roundNo` / `courtNo` 順を基準に判定する。

## 判定ルール

対戦表に含まれる全試合を `roundNo`、`courtNo` の順に並べ、保存済みの `ScheduleMatchProgress` を重ねる。

progress document が存在しない試合は `scheduled` とみなす。

1. `in_progress` が1件以上ある場合
   - 表示順で最初の試合を主対象とする
   - 複数件ある場合は進行中件数も表示する
2. `in_progress` がない場合
   - 表示順で最初の `scheduled` を次対戦とする
3. どちらもない場合
   - 全試合終了として扱う

後ろの試合を先に `in_progress` / `completed` にすることは禁止しない。
後ろの試合が終了して進行中試合がなくなった場合は、元の表示順で残っている最初の `scheduled` へ戻る。

判定は `schedule_progress/domain/schedule_progress_navigation.dart` の純粋なdomainロジックとして実装する。

## 進行summary

画面上部の省スペース表示は次の意味とする。

```text
終了試合数 / 全試合数
```

例:

```text
3 / 15
```

これは「現在3試合目」を意味しない。

確定済みでprogress summaryがまだ保存されていない場合は `0 / 全試合数` と表示する。
未確定の対戦表では進行summaryと進行対象表示を出さない。

## 進行対象表示

イベント情報カード内に、進行summaryとあわせて次を表示する。

- `in_progress` がある場合: 試合中
- `in_progress` がなく `scheduled` がある場合: 次の対戦
- 全試合終了時: 終了表示
- 対象試合のラウンド
- コート表示名
- 両側の対戦者
- 対象試合へ移動する文字ラベル付き操作

複数の `in_progress` がある場合は件数を表示し、移動先は表示順で最初の試合とする。

表示文言は既存のFlutter l10nキーを再利用するため、Issue #147では新しいARBキーを追加しない。

## 試合カードへの移動

`ScheduleRoundsView` は各試合カードに `GlobalKey` を割り当てる。

画面上部の移動操作から主対象のkeyへ `Scrollable.ensureVisible` を実行し、該当カードまでスクロールする。

自動スクロールは常時行わず、利用者が移動操作を選んだ場合だけ実行する。

対象カードは既存の状態色を維持し、枠線を少し太くすることで控えめに強調する。

将来Issue #161で参加者一覧をsticky化した場合は、スクロール先カードがsticky領域に隠れないことを実機確認し、必要ならalignmentやoffsetを調整する。

## 更新タイミング

### 試合結果入力後

Issue #166の方針どおり、結果入力ダイアログを閉じた後に `ScheduleRoundsView._loadProgress()` を1回実行する。

この再取得で次をまとめて更新する。

- 試合カードの状態・結果
- ラウンド完了表示
- `終了試合数 / 全試合数`
- 進行中／次対戦判定
- 対象カードの強調

ダイアログ内で前後移動するたびには、親画面の進行表示を更新しない。

### 手動更新後

通常生成画面と共有URL復元画面は共通の `DoublesScheduleRefreshService` と `ScheduleRoundsView` を使用する。

手動更新で最新schedule / progressが親画面へ反映された後、`ScheduleRoundsView` がprogressを再取得して進行対象を再判定する。

## 今回扱わないもの

- 実行順の保存・並べ替え
- 延期試合を任意位置へ差し込む機能
- 高度な試合状態
- コート空き状況からの自動割当
- 常時自動スクロール
- リアルタイム同期
- チーム対戦表への進行表示追加

チーム側の共通試合進行モデル接続はIssue #148で別途扱う。
