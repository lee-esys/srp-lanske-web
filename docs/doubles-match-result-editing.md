# ダブルス試合結果入力のバックグラウンド自動保存

## 目的

確定済みのダブルス対戦表で、試合状態・最終スコア・開始／終了時刻・試合メモを入力すると自動保存し、保存通信中も現在の試合への入力を継続できるようにする。

ダイアログ内では対戦表の表示順に前後の試合へ移動でき、保存失敗や複数端末によるrevision競合が発生した場合も入力中の内容を失わない。

## 編集状態

試合結果入力では、次の2つを分けて扱う。

- `baseline`
  - repositoryへ最後に保存された `ScheduleMatchProgress`
  - 次回保存に使用するrevisionを含む
- `draft`
  - ダイアログで現在入力している値
  - 試合状態、両側スコア、開始時刻、終了時刻、メモを含む

`baseline`から作成した入力値と`draft`を比較し、異なる場合を未保存状態とする。
入力を保存済み値へ戻した場合は未保存状態を解除する。

## 自動保存

入力変更後、最後の変更から500ms待って保存を開始する。

対象:

- 試合状態
- side1 / side2 スコア
- 開始時刻
- 終了時刻
- 試合メモ

短時間に複数回変更された場合は途中値をすべて保存せず、最新draftだけを保存する。

```text
3-2
↓
4-2
↓ 500ms以内
5-2
↓ 500ms以内
6-2
↓
500ms経過
↓
6-2 を保存
```

debounce時間はUI確認後に調整可能な定数として扱う。

## 保存中の追加入力

activeな保存処理は常に1件だけとする。

保存開始時に、保存に使用するbaselineとsubmitted draftを固定する。

保存通信中も現在matchの入力は継続できる。

保存成功時:

- 現在draft == submitted draft
  - 保存結果を新しいbaseline / draftへ反映する
- 現在draft != submitted draft
  - 保存結果をbaselineだけへ反映する
  - 現在draftは維持する

例:

```text
baseline: 3-2
draft:    4-2
↓
4-2 保存開始
↓ 保存中
draftを5-2へ変更
↓
4-2 保存成功
↓
baseline: 4-2
draft:    5-2
```

保存中の変更に対する500ms debounceがすでに満了している場合は、1本目の保存成功後に最新draftを続けて保存する。

まだ500ms経過していない場合は、残っているdebounceを待ってから保存する。

## UI

手動の「保存」ボタンは表示しない。

残す操作:

- 「最新の情報に更新」
- 「閉じる」
- ← / →

保存通信中は以下を非活性にする。

- 「最新の情報に更新」
- 「閉じる」
- ←
- →

保存通信中でも以下は操作可能とする。

- 試合状態
- スコア
- 開始 / 終了時刻
- 試合メモ

match情報の読込中は、現在matchの入力を含めて操作を抑止する。

## 保存状態表示

ダイアログ内には省スペースな同期状態を表示する。

保存中:

```text
保存中…
```

保存完了後:

```text
同期済み HH:mm:ss
```

同期時刻は以下の成功時に更新する。

- 自動保存成功
- 「最新の情報に更新」成功
- 前後移動先matchの取得成功

エラーがある場合は同期時刻よりエラー表示を優先する。

## 前後の試合への移動

ダイアログ上部に前後移動操作と現在位置、その下に試合状態の選択を表示する。

```text
[←]  第3ラウンド / 1コート  [→]
        （試合前｜試合中｜終了）
```

移動順は対戦表の表示データをそのまま使用する。

- `rounds` の表示順
- 各round内の `courts` の表示順
- 終了済みの試合も飛ばさない
- 先頭では前へ、末尾では次への操作を無効化する

前後移動時は移動先の1試合だけ`findMatch`で最新状態を取得する。
ページ全体や全試合のprogressは移動のたびには再読込しない。

保存通信中は移動不可とする。

保存中ではないがdirty / debounce待ちの場合は、

1. debounce待ちをキャンセル
2. 現在draftを即時保存
3. 保存中に追加変更されたdraftも含めてcleanになるまで保存
4. 保存成功後に移動先matchだけ取得
5. baseline / draftを移動先へ切り替える

保存失敗・revision競合時は現在の試合に留まり、draftを維持する。

従来の「保存して移動 / 保存せず移動 / キャンセル」の確認ダイアログは使用しない。

## 閉じる操作

保存通信中は「閉じる」を非活性にする。

保存中ではないがdirty / debounce待ちの場合は、

1. debounce待ちをキャンセル
2. 現在draftを即時保存
3. 保存中に追加変更されたdraftも含めてcleanになるまで保存
4. 保存成功後にダイアログを閉じる

保存失敗・revision競合時はダイアログとdraftを維持する。

従来の「保存して閉じる / 保存せず閉じる / キャンセル」の確認ダイアログは使用しない。

ダイアログ領域外のタップでは閉じない。

## 最新の情報に更新

ダイアログ内に「最新の情報に更新」を用意する。

未保存変更がない場合は、現在の1試合だけ最新状態を取得し、`baseline`と`draft`をその値へ更新する。

未保存変更がある場合は、debounce待ちを止めたうえで入力内容を破棄する確認を表示する。

- 更新を実行する
  - 対象matchの最新状態を取得し、成功した場合だけbaseline / draftを置き換える
- キャンセルする
  - 現在draftを維持し、500ms debounceを再開する

latest取得に失敗した場合は現在の試合とdraftを維持する。

revision競合後もこの操作によって最新revisionから編集をやり直せる。
3-way差分解消は本機能では行わず、Issue #151で扱う。

## 保存失敗・競合

保存失敗またはrevision競合時は次の状態を維持する。

- ダイアログを閉じない
- 現在の試合から移動しない
- draftを変更しない
- baselineを変更しない
- 保存中状態だけ解除する
- ダイアログ内へエラーを表示する

失敗後の自動retryは行わない。
無限retryを避け、利用者の次の入力変更、閉じる／移動時の即時保存、または「最新の情報に更新」を次の契機とする。

競合時に最新値を自動でdraftへ反映しない。

## 親画面への反映

自動保存成功ごとに、serviceから返された保存済みmatchとsummaryを親画面のprogress snapshotへ反映する。

ダイアログ内保存のたびに背景の対戦表全体は再読込しない。

ダイアログを閉じた後は`ScheduleRoundsView`のprogress再同期を1回行う。

- summary revisionが親画面と同じ場合は既存matchesを再利用する
- revisionが変わっている場合だけmatches一覧を再取得する
- event aggregateはprogress同期のためには再取得しない

ブラウザローカルの対戦表履歴は試合保存成功後に更新する。
履歴更新だけ失敗した場合に試合結果保存を取り消したり失敗扱いにはしない。

## 今回扱わない同期

以下は本機能では扱わない。

- 保存中に別matchへ先行して移動する
- match単位の複数pending save queue
- 前後matchの先読み / cache
- 試合入力中の常時polling
- Firestoreのリアルタイム購読
- 高度な3-way競合解消
- 試合メモのowner限定化

表示専用端末等の自動更新方針はIssue #174で扱う。
